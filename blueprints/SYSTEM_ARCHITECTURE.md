# SYSTEM_ARCHITECTURE.md
## Alchemy Docs — System Architecture

### 1. System Overview
Alchemy Docs is built on a **"Docs-as-Code"** architecture. This means there is no traditional database, backend server, or CMS. Instead, content lives as Markdown files in a GitHub repository. A static site generator (mdBook) compiles these files into a static website (HTML/CSS/JS) which is hosted on Vercel's global CDN.

This architecture ensures:
- **Zero maintenance:** No servers to patch or databases to manage.
- **High performance:** Static files load instantly.
- **Total version control:** Every change is tracked in Git.
- **Multi-framework scalability:** New frameworks (e.g., Builder Alchemy) are just new folders.

### 3. Component Breakdown

| Component | Technology | Responsibility |
| :--- | :--- | :--- |
| **Content Source** | Markdown (`.md`) | Where all prompts, docs, and guides live. |
| **Version Control** | GitHub | Tracks changes, triggers deployments, stores history. |
| **Static Site Generator** | mdBook (Rust) | Reads `.md` files + `SUMMARY.md`, builds HTML site. |
| **Navigation Config** | `SUMMARY.md` | Defines the sidebar structure across frameworks. |
| **Build Environment** | Vercel (Ubuntu) | Runs the `mdbook build` command with Rust installed. |
| **Hosting / CDN** | Vercel Edge Network | Serves static files globally with low latency. |
| **Routing** | `vercel.json` | Rewrites `/` to landing page, `/docs/*` to mdBook. |
| **Search Engine** | elasticlunr.js | Client-side search generated by mdBook. |
| **Theme Engine** | mdBook Default + Custom CSS | Handles dark/light mode and branding. |

### 4. Data Flow: How a New Document Reaches the User

**Step 1: Authoring**
You write a new file, e.g., `docs/src/hackathon-alchemy/02-Non-AI/phase-1/PRD.md`.

**Step 2: Version Control**
You commit and push to GitHub: `git push origin main`.

**Step 3: Webhook Trigger**
Vercel detects the push via GitHub webhook and starts a new build.

**Step 4: Build Environment Setup**
Vercel provisions a fresh Ubuntu container.
It reads `vercel.json` and runs the build command:
```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source $HOME/.cargo/env
cargo install mdbook
mdbook build docs
```

**Step 5: Compilation**
mdBook scans `docs/src/`, reads `SUMMARY.md`, and generates HTML files into `docs/book/`. It also generates a search index (`searchindex.json`).

**Step 6: Deployment**
Vercel takes the contents of `docs/book/` and distributes them to its global edge network.

**Step 7: User Access**
A user visits `https://alchemy-docs.vercel.app/docs/hackathon-alchemy/02-Non-AI/phase-1/PRD.html` and receives the fully rendered page in under 1 second.

### 5. Multi-Framework Scalability Architecture

The architecture is designed so that adding a new framework requires **zero changes to the infrastructure**.

```text
docs/
├── book.toml                 # Global config (Title: Alchemy Docs)
├── SUMMARY.md                # Global navigation (Top-level: Frameworks)
└── src/
    ├── introduction.md       # Alchemy Docs welcome page
    │
    ├── hackathon-alchemy/    # FRAMEWORK 1 (Active)
    │   ├── README.md
    │   ├── 01-AI-ML/
    │   ├── 02-Non-AI/
    │   └── ...
    │
    └── builder-alchemy/      # FRAMEWORK 2 (Future)
        ├── README.md
        ├── 01-Startup/
        ├── 02-Career/
        └── ...
```

When Builder Alchemy is ready:
1. Create the `builder-alchemy/` folder in `docs/src/`.
2. Add the `.md` files.
3. Update `SUMMARY.md` to include a new top-level section.
4. Push to GitHub.
5. Vercel rebuilds; Builder Alchemy appears alongside Hackathon Alchemy.

### 7. Security & Performance Architecture

**Security:**
- **No Backend:** No APIs to exploit, no SQL to inject, no sessions to hijack.
- **No Secrets:** The repository contains only public Markdown. No API keys.
- **HTTPS:** Automatically enforced by Vercel with free SSL.
- **DDoS Protection:** Vercel's edge network absorbs traffic spikes.

**Performance:**
- **Static Files:** HTML/CSS/JS are pre-built, so no runtime processing.
- **Global CDN:** Content is served from a location near the user.
- **Client-Side Search:** No server round-trip for search; uses local JSON index.
- **Image Optimization:** mdBook handles asset delivery; no heavy frameworks.
